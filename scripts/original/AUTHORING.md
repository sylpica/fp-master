# FP2級 オリジナル問題（四答択一）作成ガイド

最優先は **正確性**。数合わせのための問題・重複・根拠のない断定は禁止。根拠を引用で裏づけられない選択肢は作らない。

## 1. 作るもの
- `scripts/original/fporig/batches/<バッチID>.py` を1つ作る（例：`e01.py`）。`BATCH = Batch('<id>', 'FP2級 オリジナル演習 <id>（…）', [Q(...), ...])`。
- 手本：`scripts/original/fporig/batches/e01.py`（必ず先に読む）。ID は `g2o-<バッチID>-<2桁連番>`（例 `g2o-a03-07`）。
- 1問 = 2級学科と同じ **四答択一**。`ask='right'`（最も適切なもの）または `'wrong'`（最も不適切なもの）。**askに合致する選択肢がちょうど1つ**（フレームワークが検証する）。
- 選択肢の並びと正答位置はフレームワークが自動で均等化する。**選択肢文の中で「1)」「選択肢2」など他肢の番号に触れない**。
- `Q(id, topic, theme, level, stem, ask, [C×4], summary, background=, compare=, memo=)`
  - `topic`：`scripts/original/syllabus_fp2.json` の論点キー（例 `A5-4`）。担当論点を網羅するよう分散させる。
  - `theme`：画面表示用の短い分野名（既存の theme に合わせる：公的年金、生命保険の商品と仕組み、各種所得、相続税の計算 など）。
  - `level`：1基礎／2標準／3応用／4高難度／5最難関（下記）。
  - `C(text, truth, note, [(出典キー, '引用'), ...])`：`truth` はその選択肢の文が **事実として正しいか**。note は判定の理由と「どこをどう直せば正しくなるか」（誤り肢）／正しい理由（正しい肢）を **具体的に**書く（40字以上）。
  - `summary`：解答の要点（1〜2文）。`background`：制度の背景・原則と例外。`compare`：類似制度との違い。`memo`：暗記ポイント。
  - 計算を要する問題は `calc=True, calc_reason='…'`（通常演習から除外される）。知識問題は計算しない。

## 2. 根拠（引用）のルール — 最重要
- **すべての選択肢に、その判定を直接裏づける公式ページの引用**を1つ以上つける。引用は出典ページ本文（空白除去後）に **一字一句そのまま存在する**文言のみ。要約・言い換え・推測は不可。
- 法令：`from ..core import law_source` → `JK = law_source('403AC0000000090', '借地借家法')` のように登録してキーを得る。条文取得：`python3 -I scripts/original/lawtext.py find 法令名`（ID検索）／`art <ID> 条番号…`（条文表示）／`grep <ID> キーワード`。表示された本文から引用をコピーする。
- 法令以外：`register_sources({'a03_nenkin1': {'title': '日本年金機構 …', 'url': 'https://…'}})`（キーはバッチID接頭辞で衝突回避）。本文確認：`python3 -I scripts/original/lawtext.py page <URL> キーワード…`。使ってよい出典：e-Gov法令検索、国税庁（タックスアンサー・通達）、日本年金機構、全国健康保険協会、厚生労働省、ハローワーク、金融庁、日本損害保険協会、日本取引所グループ、国土交通省、法務省 等の公的機関・業界団体。**第三者の教材・問題集は出典にも参考にもしない**。
- 検証：`python3 -I scripts/original/check_batch.py <バッチID>` が「不一致 0 件」になるまで直す。
- **時点**：問題の法令基準日は 2026-04-01（`base` 既定）。e-Gov の現行条文で照合するため、2026-04-01 以後に施行される改正の絡む論点、年度ごとに変わる金額（年金額・保険料率・基準額・料率など）、頻繁に改正される数値は避け、制度の構造・要件・原則と例外・期間・割合など安定した内容を問う。区分所有法の決議要件（2026年改正）は避ける。出典で確認できない数値を使わない。
- 引用は1選択肢に複数可。ただし「noteの主張」と「引用の内容」が一致していること（引用が別の論点だったり、noteが引用にない事実を断定していたりしてはいけない）。

## 3. 良い選択肢の作り方
- 4つとも **もっともらしい完全な文**（同程度の長さ・文体）。正解肢だけ長い／短い、断定語（必ず・すべて・のみ）が誤り肢だけに偏る、といった手掛かりを作らない。
  - `check_batch.py` は、正答肢だけが最長（適切問題）／最短（不適切問題）の問題がバッチの40%を超えると警告する。`tests/data/original.test.ts` は全体の割合の上限（現在32%）とバッチごとの40%を検査する。誤り肢を短く作りがちなので、誤り肢にも適用条件や主語を書き込み、正しい肢と同程度の長さにすること。
- 誤り肢は、適用条件・期限・年齢・割合の一部違い、原則と例外の入れ替え、よく似た制度の取り違え、対象者の違い、正しい説明に1点だけ誤りを混ぜる、など **条文で確実に誤りと言える**ものにする。曖昧な文・不自然な日本語・出題意図の読み取りに依存する文は不可。
- 「最も適切」問題は、正解以外の3肢が **明確に誤り**であること。「最も不適切」問題は、正解以外の3肢が **明確に正しい**こと。他に正解になりうる肢がないか自分で再点検する。
- 同一論点の言い換えだけの類題を量産しない。バッチ内で論点・切り口を分散する。

## 4. 難易度
- Lv1 基礎（用語・基本ルール）／Lv2 標準（本試験の標準）／Lv3 応用（要件の細部・数値・期間）／**Lv4 高難度**（細かな適用条件・複数制度の比較・例外・低頻度論点・紛らわしい正誤）／**Lv5 最難関**（複数論点の組み合わせ・例外/特例の適用判断・段階的整理が必要・一見複数が正しそう）。
- 難易度は**定義への該当性だけで付ける**。分布の目標値（割合）は設けない（旧ルール「各バッチで Lv4＋Lv5 を50%以上」は、Lv5 の過剰付与を招いたため 2026-11-12 に廃止。外部監査 R2-M08）。Lv5 は「複数論点の組み合わせ＋例外/特例の適用判断または段階的整理」が実質的にある場合に限る。「例外を知っているか」だけの単一論点は Lv4、単一論点の標準的な適用・当てはめ計算は Lv3。実技ケースは ①資料で計算式・数値表を与えているか（与えていれば負荷が下がる）②例外・特例の適用判断で結論が分岐するか ③小問間で前の答えを使う段階計算か、の3点で判定する。難しさは知識の深さから作る。**FP1級相当の知識が必要な問題は不可**。試験範囲（syllabus）外は不可。

## 5. 禁止事項
- 引用の捏造・改変、出典で確認できない事実の断定、問題集等の丸写し、公式過去問そのものの再掲。
- 他のバッチ・既存ファイル（`core.py`、他バッチ、`src/`、`docs/`）の編集。`build_content.py` の実行、git操作。自分のバッチファイルのみ編集する。

## 6. 四択以外（実技ケース・学科の ○×／語群補充／組合せ／三択）
`scripts/original/fporig/cases.py`（`Case_` / `CaseBatch` / `NUM` / `SEL` / `TF` / `T` / `X`）で書く。手本：`batches/j01.py`（実技）、`batches/k01.py`（学科）。
- 実技：`CaseBatch('j01', タイトル, 'j2', [K(...)])`、ID `j2o-<バッチ>-NN`、設例（`materials`：`T`表／`X`文章）＋3〜5小問、小問は `NUM`（数値）／`SEL`（選択）／`TF`（○×）。出力 `j2o_<バッチ>.json`。
- 学科の四択以外：`'g2'`、ID `g2n-<バッチ>-NN`、`tags=('○×',)`／`('語群補充',)`／`('組合せ',)`／`('三択',)`。出力 `g2n_<バッチ>.json`（2級学科の模擬試験には含まれない）。
- **数値の正答は、年度で変わる金額を設例に与えたうえで、バッチ内のPythonコードで計算した値**を渡す（手入力しない）。端数処理は問題文で指示し、コード側で丸める。`steps` に計算過程を書く。
- 各小問に公式ページの引用（`ev`）を必須とする（四択と同じ検証）。法令に書かれていない数学的な計算のみ `math=True` で省略可。ケース全体では引用1つ以上。
- 単独小問の選択式（組合せ・三択）は全選択肢の判定理由（`option_notes`）が必要。語群補充は同じ選択肢リストを各空欄の `SEL(..., shuffle=False)` に渡す。
- 数値小問を含むケースは自動で `requiresCalculation=true`（通常演習から除外され、計算トレーニング・模擬試験で出題）。`calc_reason` を書く。
- 検証：`python3 -I scripts/original/check_batch.py <バッチID>`。法令基準日（2026-04-01）以後の改正、年度ごとに変わる金額（年金額・控除額・保険料率など）は設例で与えるか避ける。
