各項目：発生箇所／再現条件・実際の動作／期待する動作／根本原因／影響範囲／対応・テスト／残存リスク。

### High

**EXT-H01 選択肢の長さで正答を推測できる（FP2 オリジナル四択）** — 未解決（再発防止は実装済み）
- 発生箇所：`src/content/questions/g2o_*.json`（原稿 `scripts/original/fporig/batches/*.py`）。
- 実測：「最も適切なもの」434問のうち、正答肢だけが一番長い問題が **265問（61.1%）**、正答肢が長さ1位（同率含む）なのは 318問（73.3%）。「最も不適切なもの」392問では正答肢が短い側に偏る（長さ3〜4位が 244問＝62.2%）。両方向をあわせた「長さが正答の手掛かりになる問題」は **387/825（46.9%）**。4肢がランダムなら約25%で、公式問題は同じ指標で 適切 28.5%・不適切 24.5%。
- 期待：選択肢の文章量から正答を推測できない（指令書 第9節）。
- 根本原因：誤り肢を「1点だけ誤りを混ぜる」「条件を削る」方式で作ると短くなり、正しい肢は適用条件を書き込むため長くなる。AUTHORING.md に禁止は書かれていたが、check_batch に検査がなかった（72バッチ中 43バッチが基準40%超）。
- 影響：95%チャレンジの初見正答率・到達度が知識ではなく受験テクニックで底上げされうる。本試験（公式問題には偏りがない）への転移が下がる。
- 対応（本PR）：`check_batch.py` にバッチ単位の警告（正答肢だけが最長／最短の割合が40%超で問題IDを列挙）を追加。`tests/data/original.test.ts` に全体の上限テスト（現状 46.9% → 上限 0.47。悪化を禁止し、書き直しのたびに下げる。目標35%以下）を追加。
- 引き継ぎ（Muse）：警告が出た問題の誤り肢に適用条件・主語を補う、または正答肢の冗長な修飾を削り、4肢の長さをそろえる。引用（evidence）は変えずに文面だけ直せば `build_content.py --offline` で照合状態を保ったまま再生成できるが、文面が引用の主張と一致することの確認と `check_batch.py`（オンライン）での再照合を行うこと。

### Medium

**EXT-M02 統合復元で、古いバックアップが新しい復習予定・メモを上書きする** — 修正済み
- 再現：バックアップ後に学習を進め、その古いバックアップを「統合する」で復元すると、srs（復習予定）・notes・termState・sessions が同じキーのバックアップ側で上書きされ、学習が巻き戻る。画面の説明は「今のデータを残し、重複しない履歴を追加」で、動作と矛盾していた。
- 根本原因：`restoreBackup` の merge が attempts/mockResults/reports 以外を一律 `bulkPut`。
- 対応：srs は `last`、notes・termState・sessions は `updatedAt` で新しい方を残す（`backupRowWins`）。ブックマーク・あとで解く・設定は従来どおり（存在のみ・設定は上書き）。結合テスト2件（古いバックアップで巻き戻らない／バックアップが新しければ採用する）を追加。
- 残存リスク：端末の時計が大きくずれていると新旧判定が逆転しうる。

**EXT-M03 置き換え復元の前に今のデータを退避しない** — 修正済み
- 再現：「置き換える」は確認ダイアログのみで現在のデータを削除する。取り違えたファイルで実行すると元に戻せない。
- 対応：置き換えの直前に現在のデータを `fp-master-before-restore-<日時>.json` として自動で書き出し、完了メッセージにファイル名を表示（`src/pages/Data.tsx`）。E2E は統合モードのみを通すため、置き換え経路のブラウザ確認は未実施（残課題）。

**EXT-M04 公開デプロイが CI（E2E）の成功を待たない** — 修正済み
- 再現：`deploy.yml` は main への push で CI と並行実行し、vitest と build のみで公開していた。E2E が失敗したコミットも公開されうる。
- 対応：`workflow_run`（CI が main の push で成功）で起動し、CI が検証したコミット（head_sha）を公開するよう変更。手動実行は維持。CI ワークフローに `permissions: contents: read` を追加（EXT-L02）。

**EXT-M05 週次の出典変更検知が毎回誤検知の Issue を作る** — 修正済み
- 再現：Issue #25（2026-11-02）の差分は `source-check.json` の照合日（checkedAt）784行の更新のみで、照合件数（照合済み1,633／要確認551）に変化はない。日付が毎回変わるため、実際の変化がなくても毎週 Issue が作られる（警報疲れ）。
- 対応：`source-check.yml` で、`source-check.json` の差分が checkedAt 行だけなら「変更なし」とする。手元で3ケース（日付のみ→変更なし／missing の変化→変更あり／他ファイルの変化→変更あり）を確認。

**EXT-M06 問題データのキャッシュに30日の有効期限があり、オフラインのみの利用が続くと問題を読めなくなる** — 修正済み（実機未検証）
- 発生箇所：`vite.config.ts` の runtimeCaching（CacheFirst・`maxAgeSeconds: 30日`）。
- 根拠：workbox の ExpirationPlugin は、キャッシュの応答が maxAgeSeconds を過ぎると使わずにネットワークへ取りに行く。問題データのチャンクは内容ハッシュ付きのファイル名で中身が変わらないため期限は不要で、最後のオンライン取得から30日を過ぎたオフライン起動では問題データの読み込みに失敗しうる。
- 対応：maxAgeSeconds を外し、古い版の整理は maxEntries（最近使っていないものから削除）に任せる。オフライン30日経過の再現はブラウザ時計の操作が必要で、本環境では未実施。

**EXT-M07 計算トレーニング（容積率）が法令上ありえない指定容積率を出題する** — 修正済み
- 再現：`floor-area-ratio` 生成器が「近隣商業地域・指定容積率600％」を出題しうる（建築基準法52条1項3号で近隣商業地域は10/10〜50/10）。
- 対応：近隣商業地域の候補を 200/300/400/500％に変更。単体テストで、全難易度×500シードの指定容積率が用途地域で定め得る値に含まれることを検査。
- 影響：同じシードの容積率問題は指定容積率だけ変わることがある（計算問題は復習スケジュールの対象外で、履歴の正誤は記録時点の問題に対するもの）。
